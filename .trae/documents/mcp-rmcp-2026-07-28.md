# 改造 MCP：使用官方 rmcp SDK 实现 MCP 2026-07-28

## Context（背景）

当前 fluen-kb 的 MCP 层是**手写 stdio 协议层**（[src/mcp/mod.rs](file:///d:/Dev/fluen-kb/src/mcp/mod.rs)），硬编码协议版本 `2024-11-05`，实现 `initialize`/`ping`/`tools/list`/`tools/call`。经联网核实，这属于 MCP 1.0 时代的旧规范，**不满足原生 MCP 2.0（2026-07-28 无状态规范）**。

用户要求改用官方最新 MCP 库。官方 Rust SDK 是 **`rmcp`**（crates.io `rmcp` v3.x，官方仓库 modelcontextprotocol/rust-sdk），实现稳定版 MCP `2026-07-28` 并向后兼容 `2025-11-25`。本次目标：用 `rmcp` 重写 MCP 层，确保符合规范，同时**保留现有 10 个工具与公开 API 形态**，最小化破坏。

## 设计决策

- **实现方式**：手工实现 `rmcp::handler::server::ServerHandler` trait（`list_tools` / `call_tool` / `get_info`），**不**引入 `#[tool]` 宏与 `schemars`。因为工具 JSON Schema 已在 [src/mcp/tools.rs](file:///d:/Dev/fluen-kb/src/mcp/tools.rs) 用 `serde_json` 构建，可复用，避免额外依赖与派生。

- **协议版本**：`get_info()` 显式返回 `ProtocolVersion::V_2026_07_28`，能力声明 `capabilities.tools`。rmcp 默认即无状态（无 `initialize` 握手，支持 `server/discover`），符合原生规范。

- **传输**：`rmcp::transport::stdio()`（tokio `Stdin/Stdout`），`serve().await?` 阻塞等待。

- **公开 API 保持**：保留 `pub fn run_stdio(kb: Kb) -> KbResult<()>`（同步、阻塞，内部起 tokio runtime）；另提供一个 async 入口 `pub async fn serve_stdio(kb)` 供已运行在 tokio 中的宿主调用（避免嵌套 runtime 崩溃）。

- **工具结果**：白名单文本内容（`content` 含序列化 JSON，保持旧 CLI 行为）+ 可选 `structuredContent`，并正确设置 `isError`。

## 改动文件

### 1. `Cargo.toml`

- `mcp-server` feature 改为：

  - 移除 `"dep:serde"` 语义不变（仍需 serde/serde\_json 建 schema），改为依赖 `dep:rmcp`、`dep:serde`、`dep:serde_json`、`dep:tokio`、`index`。

- dependencies 增加：

  - `rmcp = { version = "3", optional = true, default-features = false, features = ["server", "transport-io"] }`

  - 让 `tokio` 在 `mcp-server` 下可用 runtime：把 `tokio` optional 依赖 features 扩展为 `["rt", "rt-multi-thread"]`（供 `run_stdio` 内部起多线程 runtime）。

- dev-dependencies `tokio` 已含 `rt-multi-thread, macros`，可写 `#[tokio::test]`。

### 2. `src/mcp/mod.rs`（重写）

- `#[derive(Clone)] pub struct KbServer { kb: Kb }`，实现 `ServerHandler<RoleServer>`：

  - `get_info()` → `ServerInfo { protocol_version: V_2026_07_28, capabilities: ServerCapabilities { tools: Some(ToolsCapability{ list_changed: None }), .. }, name: "fluen-kb", version: env!("CARGO_PKG_VERSION"), .. }`（字段名以 rmcp 3.x 实际为准）。

  - `list_tools(_)` → `ListToolsResult`（复用 `tools.rs` 的 schema 数组），保持确定性顺序。

  - `call_tool(request, _)` → 按 `request.name` 分发到现有工具处理函数，返回 `CallToolResult{ content: [text(json)], structured_content: Some(json), is_error, .. }`；参数错误返回 `Err(McpError)` 以产生 JSON-RPC 错误。

- `pub fn server(kb: Kb) -> KbServer`。

- `pub async fn serve_stdio(kb) -> KbResult<()>`：`KbServer::new(kb).serve(stdio()).await?.waiting().await?`。

- `pub fn run_stdio(kb: Kb) -> KbResult<()>`：`tokio::runtime::Builder::new_multi_thread().enable_all().build()?.block_on(serve_stdio(kb))`。

- 移除手写的 `serve`/`initialize`/`ping`/`Request`/`PROTOCOL_VERSION`。

### 3. `src/mcp/tools.rs`（重构，复用逻辑）

- 保留全部参数解析辅助（`str_arg`/`opt_enum`/`parse_relations` 等）与 10 个工具处理函数（`query/create_entry/lint/…`）。

- 这些函数改为接收 `(name, args: &Value)` 或保持 `(kb, params: &Value)`；`list_tools` 的定义/顺序抽成 `pub fn tool_definitions() -> Vec<Tool>`，每项用 `Tool::new(name, description, schema)`。

### 4. `tests/mcp_cases.rs`（重写，验证 rmcp 路径）

- 用 `#[tokio::test]` 直接在 `KbServer` 上调用 `list_tools`/`call_tool`：

  - `initialize_and_list_tools` → 改名 `list_tools_exposes_ten_tools`：校验 10 个工具名齐全、顺序确定。

  - `create_query_delete_lint_via_tools` → 走 `call_tool` 依次 create→query→lint→delete，校验 behavior 不变。

  - `bad_arguments_return_jsonrpc_error` → 缺参 call\_tool 返回 `Err(McpError)` / `isError`。

- （可选，若时间允许）用 `tokio::io::duplex` + rmcp client 做一次真实 `server/discover`→`tools/list` 的线上握手断言，端到端验证 2026-07-28。

### 5. `README.md`

- 更新 MCP 章节：改为"基于官方 rmcp SDK（MCP 2026-07-28）"，更新 feature 表里 `mcp-server` 的依赖描述；去掉手写协议层表述。

## 验证

1. `cargo build --features mcp-server` / `cargo build --all-features` 编译通过。
2. `cargo test --all-features`：全部（含重写后的 mcp\_cases）通过。
3. `cargo clippy --all-targets --features mcp-server`：无新的违规（项目 `.unwrap` deny 由 crate 顶层测试 allow 宏已处理）。
4. 端到端：用 MCP 官方 client 或手动向 `run_stdio` 喂入 `{"method":"server/discover"}` 与 `{"method":"tools/call","params":{name:knowledge_create_entry,...}}`，确认返回 `resultType`、工具可调用。

## 风险与说明

- rmcp 3.x `CallToolResult`/`ServerInfo`/`arguments` 的**精确字段名**在写码时以本机 `cargo doc` 或 crates.io 为准微调（如 `structured_content` 蛇形 vs 字段命名）。

- `run_stdio` 内部新建 runtime，若宿主已处于 tokio runtime 会 panic——故同时提供 `serve_stdio` async 入口并在 README 说明调用条件。

- `mcp-server` 不再复用手写 `mcp::serve(kb, reader, writer)` 测试辅助，相关测试一并移除。
